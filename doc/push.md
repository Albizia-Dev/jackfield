# Push-приглашения и токены

Jackfield не содержит Firebase SDK и не задаёт бизнес-формат push. Host-приложение проверяет отправителя, TTL, привязку к пользователю и формирует wire v1 для нативной точки входа. Сервер отправляет приглашение с новым стабильным `CallId`; повторный push с тем же событием не должен создавать второй звонок. После входа в Flutter приложение сверяет реальное состояние звонка с сервером.

На Android собственный `FirebaseMessagingService` host-приложения преобразует FCM data message и вызывает `JackfieldPushReceiver.reportIncomingCall(context, payload)`; обновление токена передаёт в `JackfieldPushReceiver.updatePushToken`. На iOS host настраивает APNs/PushKit entitlement и background modes; адаптер обрабатывает объект `jackfield` в VoIP payload. На Web host Service Worker импортирует worker пакета, устанавливает обработчики и связывает приглашение с `installationId` и `sessionId`; подписка Push API допускается только из пользовательского жеста. На macOS адаптер не получает push-токены. Windows/Linux пока не имеют рабочего адаптера. Подробности и точный payload: [Android](android.md), [iOS](ios.md), [Web](web.md).

Один контроллер приложения владеет подпиской `pushTokenUpdates` и одной последовательной очередью операций над устойчивым локальным/серверным хранилищем. В начале цикла он буферизует обновления и запрашивает `pushTokens()` с timeout. Полная замена из `PushTokenSnapshot.tokens` выполняется в этой же очереди. Пока она выполняется, новые события остаются в буфере. После её успешного завершения контроллер одним синхронным шагом ставит буфер в очередь по порядку, очищает его и переключает обработчик на постановку новых событий в очередь. Между этими действиями нет `await` и нет окна, в котором событие осталось бы ни в буфере, ни в очереди. `PushTokenUpdate.removed` означает удаление старого значения. Пример шагов есть в [README](../README.md).

Ошибка snapshot-запроса, timeout, stream или любой операции очереди завершает текущий цикл. Контроллер ловит ошибку каждой операции, отменяет старую подписку, дожидается текущей записи, отбрасывает ещё не начатые операции и результат устаревшего snapshot-запроса, затем с ограниченным backoff начинает **полный** цикл заново: новая подписка, буфер и новый снимок. Идентификатор поколения не позволяет позднему ответу старого запроса изменить новое состояние. Нельзя одновременно запускать два цикла или позволять старому `replaceAll` продолжаться после старта нового: иначе старая запись перетрёт новую сверку. После logout контроллер отменяет цикл; после restart, смены пользователя и периодически выполняет полный цикл и сверяет серверное состояние. Серверные upsert/remove должны быть идемпотентными, но сами по себе не защищают от устаревшего снимка.

API не содержит revision/timestamp и не подтверждает атомарную границу запуска stream относительно снимка. Поэтому описанный порядок сохраняет полученные обновления, но не доказывает, что провайдер или платформа не пропустили обновление: периодическая полная сверка остаётся необходимой. При неуспехе `pushTokens()` локальные значения нельзя считать актуальными. `pushTokens()` сам не запрашивает permission. Не логируйте значения токенов. Для Web подписка из жеста выполняется отдельно через `JackfieldWeb.subscribePushFromUserGesture`.

`server_example/` показывает одну ручную схему с FCM и callback endpoint. Его in-memory состояние, service-account credentials из окружения и тестовые маршруты не входят в runtime пакета. Unit тесты сервера не подтверждают доставку реального push на устройство.
