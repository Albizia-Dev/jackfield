# HTTPS callbacks Jackfield v1

HTTPS callbacks включаются через `CallbackConfiguration` при `initialize`.
Отсутствие конфигурации отключает HTTP-доставку. Flutter inbox и HTTP outbox
имеют отдельные подтверждения: успешный callback не подтверждает событие во
Flutter, а `acknowledgeEvents` не подтверждает HTTP-доставку.

## Запрос

Адаптер отправляет `POST` на настроенный HTTPS endpoint с заголовками
`Content-Type: application/json`, `Authorization: Bearer <token>` и
`Idempotency-Key: <eventId>`. Перенаправления не следуются. Тело —
версионированный JSON envelope. Канонический пример находится в
`test/fixtures/callback_answer_requested_v1.json`:

```json
{
  "version": 1,
  "event": {
    "version": 1,
    "callId": "call-1",
    "eventId": "event-7",
    "sequence": 2,
    "occurredAt": "2026-09-23T05:00:00.000Z",
    "type": "answer_requested",
    "actionId": "action-3",
    "deadline": "2026-09-23T05:00:30.000Z"
  }
}
```

`event` использует тот же wire v1, что и Flutter event stream. Сервер
дедуплицирует запросы по `eventId` и учитывает `sequence` внутри `callId`.
Повтор с тем же `eventId` является штатным. `actionId` обозначает действие,
которое приложение должно завершить отдельно; HTTP ACK не завершает действие.

Тело не содержит bearer token, media credentials или данных звонящего.
Credentials нельзя включать в события, diagnostics, ошибки и логи. Адаптер
держит token в защищённом системном хранилище, если оно доступно. Ротация
credentials возобновляет очередь после паузы авторизации.

## Политика доставки

`RetryPolicy.standard` классифицирует результат одной попытки:

| Результат | Действие |
|---|---|
| Любой `2xx` | Подтвердить только HTTP receipt. |
| `401` или `403` | Приостановить HTTP очередь до ротации credentials; оба receipt остаются. |
| `429`, `5xx` или ошибка сети | Повторить с ограниченной задержкой. |
| Остальные `4xx`, `3xx`, другие ответы | Терминальная ошибка; не повторять. |
| Возраст события достиг TTL | Терминальная ошибка независимо от HTTP-ответа. |

Номер попытки начинается с 1. Детерминированная база exponential backoff —
1, 2, 4, 8 секунд и далее, максимум 15 минут. Положительный `Retry-After`
имеет приоритет, но тоже ограничен 15 минутами. Нулевой или отрицательный
`Retry-After` игнорируется. Платформенный адаптер добавляет jitter к расписанию,
не выходя за пределы TTL; общий Dart policy не использует случайность.

TTL по умолчанию — 24 часа от `occurredAt`. По достижении TTL событие
больше не отправляется. Максимальный размер HTTP очереди по умолчанию —
1000 событий; отказ в admission должен быть типизированной ошибкой хранения.
Адаптер сохраняет статус попытки, время следующей попытки, терминальный исход
и состояние паузы долговечно. `CallbackDispatcher.deliver` меняет общий журнал
только при `2xx` и `401/403`; решения `RetryLater` и `DoNotRetry` возвращаются
адаптеру для его долговечного outbox. После терминального исхода запись больше
не выбирается для HTTP отправки, но Flutter receipt остаётся независимым.

Порядок сохраняется для событий одного `callId`; задержка одного звонка не
блокирует другой `callId`. Сетевой запрос выполняется платформенным адаптером
без необходимости работающего Flutter там, где ОС позволяет фоновое выполнение.
Долговечное хранилище, планировщик, jitter и фактическая HTTPS отправка не
реализуются общим Dart policy.
