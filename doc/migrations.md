# Версии и миграции

Публичный Dart API и wire envelope имеют независимые границы совместимости. Текущий envelope требует целочисленный `version: 1`; неизвестная, дробная или повреждённая версия даёт `protocolFailure`/`JackfieldProtocolException`, а не угадывается. `CallId`, `ActionId` и `EventId` имеют разные назначения. Не переиспользуйте идентификатор звонка для нового call attempt и не преобразуйте старые события в новые IDs при восстановлении.

Платформенное хранилище должно сохранять неподтверждённые Flutter и HTTP receipts, sequence, action outcomes и deadlines через обновление. Android использует Room schema v3: v1→v2 добавляет отпечаток отклонённых callback credentials, v2→v3 — nullable `calls.expiresAt` без очистки старых звонков или событий. Старые snapshots без ring deadline остаются читаемыми, но deadline применяется только к новым входящим вызовам. iOS SQLite schema v1 хранит snapshot как Codable JSON, поэтому новое optional-поле `expiresAt` обратно совместимо; старая v0 мигрирует транзакционно, перенумеровывая дубли `(callId, sequence)` без сброса receipts. macOS использует тот же snapshot-контракт и хранит привязку callback endpoint к отпечатку токена; legacy Keychain token переносится только при совпадении отпечатка. Web использует IndexedDB с versioned worker state. Конкретные условия описаны в [платформенных руководствах](architecture.md).

Перед обновлением проверьте реальный replay с неподтверждённым событием, повтор `completeAction` и ACK, ротацию callback credentials после `401/403`, отчёт `capabilities()` и запуск с прежней базой. Не удаляйте локальные данные как способ «исправления» несовместимой версии: это теряет доказательства действий и pending deliveries. При смене wire v1 потребуется новая явная версия и набор канонических fixtures; молчаливая смена полей запрещена.

Windows/Linux сейчас являются scaffold, их схемы и сценарии миграции не подтверждены. Текущая версия пакета `0.0.2` не обещает стабильный SemVer контракт; перед публичным релизом нужно зафиксировать API и проверить реальные устройства/провайдеры.
