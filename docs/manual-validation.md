# Ручная проверка Jackfield

`example/` — ручной интеграционный стенд публичного API. Он не входит в runtime библиотеки и не заменяет проверку устройства, операционной системы и push провайдера. Jackfield управляет системным представлением звонка и локальными событиями; приложение отвечает за медиа, авторизацию и настоящий сигналинг. Переключатель на вкладке «Звонки» лишь имитирует ответ сигналинга.

## Подготовка

1. Запустите `cd example && flutter run` на целевой платформе. Для Web нужен HTTPS или localhost, разрешённые уведомления и Service Worker. Для iOS/APNs, Android/FCM и Web Push потребуются отдельно настроенные провайдеры и разрешения; сам пример их не регистрирует.
2. На вкладке «Диагностика» проверьте фактический механизм, возможности, разрешения и счётчики. `unsupported` — ожидаемый честный результат там, где функция недоступна.
3. В каждом опыте используйте новый `Call ID`. Оставьте поле пустым, чтобы стенд создал локальный идентификатор.

## Звонки и события

1. Нажмите «Показать входящий». Проверьте системный UI или уведомление, соответствующее показанному механизму. Нажмите Answer в системном UI. В журнале найдите `AnswerRequested`, результат имитации сигналинга, `completeAction` и `ACK` в этом порядке.
2. Повторите с выключенным «Имитация сигналинга успешна». Ожидается `ActionResult.failure`, затем ACK. Успех ACK означает лишь обработку Flutter события и не означает успешный ответ на звонок.
3. Нажмите «Начать исходящий», затем «Завершить выбранный». Проверьте видимый результат каждой команды и конечное состояние на целевой платформе. В этом стенде исходящий вызов не подключает медиа.
4. Для проверки replay создайте входящий, получите событие и перезапустите Flutter до ACK (для этого потребуется отладочная пауза в контроллере). Повтор события должен иметь тот же `eventId`; повторный ACK безопасен. Обычный UI стенда ACK отправляет сразу после обработки и потому сам по себе не создаёт это окно.

## Callback и push

1. Введите тестовый HTTPS endpoint и тестовый bearer token на вкладке «Диагностика», нажмите «Применить callback». Поле токена очищается. Успех и ошибки показываются в статусе и журнале; этот ввод вызывает только публичный `initialize`.
2. Используйте отдельный тестовый сервер для проверки фактической автономной доставки, паузы на 401/403 и восстановления после смены токена. Вкладка показывает счётчик HTTP очереди и флаг auth pause, но сама не отправляет HTTP запросы.
3. Нажмите «Показать токены». Снимок `pushTokens()` не запрашивает разрешение. Значения выводятся для ручного копирования: пользуйтесь только тестовыми токенами и не снимайте скриншоты с действующими секретами. В примере нет регистрации FCM/APNs/Web Push и нет отправки push.

## Границы доказательства

Успешные unit тесты, анализ и сборка показывают корректность кода в этих условиях. Они не доказывают доставку APNs/FCM/Web Push, работу lock screen/DND/force stop, фоновую доставку callback или поведение конкретного устройства. Записывайте модель устройства, версию ОС, режим приложения, разрешения, провайдера, шаги и фактический результат отдельно.
