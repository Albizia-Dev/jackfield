# Версии и миграции

Публичный Dart API и wire envelope имеют независимые границы совместимости. Текущий envelope требует целочисленный `version: 1`; неизвестная, дробная или повреждённая версия даёт `protocolFailure`/`JackfieldProtocolException`, а не угадывается. `CallId`, `ActionId` и `EventId` имеют разные назначения. Не переиспользуйте идентификатор звонка для нового call attempt и не преобразуйте старые события в новые IDs при восстановлении.

Платформенное хранилище должно сохранять неподтверждённые Flutter и HTTP receipts, sequence, action outcomes и deadlines через обновление. Android использует Room schema v2 (миграция v1→v2 добавила отпечаток отклонённых callback credentials без очистки событий). iOS SQLite schema v1 мигрирует старую v0 транзакционно, перенумеровывая дубли старых `(callId, sequence)` без сброса receipts; будущая неизвестная версия отклоняется. macOS SQLite хранит snapshots/receipts и привязку callback endpoint к отпечатку токена; legacy Keychain token переносится только при совпадении отпечатка. Web использует IndexedDB с versioned worker state. Конкретные условия описаны в [платформенных руководствах](architecture.md).

Перед обновлением проверьте реальный replay с неподтверждённым событием, повтор `completeAction` и ACK, ротацию callback credentials после `401/403`, отчёт `capabilities()` и запуск с прежней базой. Не удаляйте локальные данные как способ «исправления» несовместимой версии: это теряет доказательства действий и pending deliveries. При смене wire v1 потребуется новая явная версия и набор канонических fixtures; молчаливая смена полей запрещена.

Windows/Linux сейчас являются scaffold, их схемы и сценарии миграции не подтверждены. Текущая версия пакета `0.0.1` не обещает стабильный SemVer контракт; перед публичным релизом нужно зафиксировать API и проверить реальные устройства/провайдеры.
